quickstart

Three steps from zero to a persistent remote session.

1 · installPut Vamp Host (full) or Vamp Terminal Host (light) on the Mac.
2 · pairEnter the six-digit code; approve the signed request on the Mac.
3 · attachOpen the iOS app or the private Safari URL and attach a tab.
4 · persistUse tmux for long work; tabs survive disconnects and reattach cleanly.

which host?

Vamp Host — remote display, input, and Terminal Mode in one. Vamp Terminal Host — terminal and Safari control only, nothing graphical. Both speak the same signed pairing protocol, so clients work with either.

$ scripts/package-vamp-hosts.sh --clean
# → dist/VampTerminalHosts/ (arm64, ad-hoc signed)

safari workspace

A terminal-only browser surface styled like a task chat, bound to loopback and published privately with Tailscale Serve. Explicit approval cards gate every command.

$ vamp browser serve
# → http://100.x.y.z:9475/?pair=•••••• (tailnet only)
  • Up to eight concurrent browser CLI tabs
  • Allow / Always allow / Deny approval cards
  • Two-way clipboard with the host

cli reference

The vamp wrapper is script- and agent-friendly (structured exit codes, --json output).

$ vamp ensure # start host, wait ready
$ vamp status --json # machine-readable state
$ vamp terminal start --session work # persistent shell
$ vamp terminal attach work # reattach from a tab
$ vamp browser serve # safari via tailscale

agent launchers

Each supported CLI gets a stable named PTY inside tmux. Reconnect from any client to the same running agent.

$ vamp terminal agent <name> --session <name>

security model

  • Terminal Mode is opt-in; disabling it closes every active PTY
  • Signed pairing requires visible host approval per device
  • Safari control: loopback + Tailscale only, never public traffic
  • Session/terminal IDs route every tab independently
  • No account backend, public forwarding, or hosted relay
